## I. 所有者最终决策（覆盖全文其他表述）

### I.1 第一轮决策（方向性）

1. 路线：v0.7.0 全量重构。允许拆分/合并/重编号 `docs/design` 篇章；00 术语表仍是全仓库唯一术语基准；README 与 `adr/README` 索引同步更新。
2. ADR：允许直接修订 ADR-0001~0006 正文；每份被修订的 ADR 文内必须有 `## 修订历史` 段注明 v0.7.0 改了什么、为什么；新增 ADR 从 0007 起编号。
3. 归档：把 v0.6.0 现行文档按 `docs/archive/v0.5.0` 的约定（含 `ARCHIVE.md`）快照到 `docs/archive/v0.6.0/`，**包含 `docs/CHANGELOG.md`**。git tag `v0.6.0` 已存在（指向 commit `3e65b64`），ARCHIVE.md 直接引用。
4. 远期开放问题中只有"边缘离线账本一致性"纳入本轮正式设计（设计文档 + ADR-0010）。Trust 对象、多主体/多节点分布式一致性、Level-3 CaMeL 级信息流、Provider 路由/fallback、`gen_ai.*`/`fysun.*` 长期关系全部保持开放，只在开放问题清单登记。
5. Level-1 Runtime 原生（非 MCP）工具：资格化要求 `describe()` 声明 `native_effect_tools[]`；Policy 可据此拒绝资格化或降级 conformance；威胁模型 conformance 表按 Runtime 类型分列 F3/F5/F7/F9；另增 hooks.json（Claude Code / Codex / DSH 兼容的 PreToolUse command hook，退出码 2 阻断）路径作为"Level-1b，仅阻断，不计入 conformance 主路径"的补充。
6. Level-1 下 F5：限定为"OS 管理的 secret 与经 `fysund` 代理的 Provider"；harness 自持模型凭据列入威胁模型"不防"；部署指引：把 harness 的 OpenAI 兼容 base URL 指向 `fysund` 代理。
7. agentgateway：仅借用 Pass/Reject/Mutated 语义与 Cedar 格式，`fysun-mcp-guard` 自实现；独立成 ADR-0012；关闭 08 Q10 / ADR-0002 D7。
8. Effect 类别分类来源（ADR-0008）：三源合一——Capability 契约 `bounds.tool_effects[]` 必填；Resource 目录可登记 MCP server 工具缺省类别；Policy 可覆盖；未分类工具一律 `external_mutation`（fail-closed）；MCP tool annotations 仅作输入不作依据。
9. M2a 的 Level-1 harness：DSH headless 模式；文档登记查证项"需查证 DSH headless 是否有独立于 bundle 的原生工具"。
10. 来源标签：保留 ADR-0004 词汇；工具结果一律 `untrusted_external`，唯一升级路径是 Verification / Memory 准入；删除 02 §2.9、09 §2、04 §2.7（A2A 可信 Agent Card）三处例外；迁移清单更正为"CognitiveOS 有上下文层部分先例（`cognitive-kernel/src/context.rs` 的 `LoadedContextItemTrustLevel {Control, Authoritative, Verified, Untrusted}`，仅覆盖上下文装配、未沿参数流传播到 Effect），FysunOS 扩展新建"。
11. DSH Level-2 审批：`fysund` 是唯一 answerer；`fysun-dsh` 在 DSH `approval/request` waterfall 拦截、不 `next()`、全部转给 `fysund` 的 Approval 对象；DSH 自身审批卡片失效，审批 UI 由 `fysund` 提供。
12. 小项全部按推荐（详见 §B 各篇）：`predicted_effect` 可选；Level 速记保留但禁入标识符；Policy 输出只保留四值 outcome；"全量供给"改"供给（Trust 除外）"；Execution `waiting` 加 `reason`；Approval 结果集封闭 fail-closed 且只引用 ActionIntent；Agent Teams 只有 Handoff 入账；DSH 精确钉版 + 每日漂移预警；sources.md 修正 Cordis 版本；Memory 写入不称"内部 Effect"；`policy.describe(policy_id?)`；`audit/observed` 事件；ADR-0004 D5 负例归属；`handoff_accept` 触发条件；Runtime 作为通用 Resource 类型与资格化纪元；下游 MCP server 凭据边界；Level-1 context_view / deliver_input 投递路径。

### I.2 第二轮决策（蓝图确认与新问题）

- 文档地图：接受 §A 的 00–13 十四篇重组方案；边缘离线一致性并入 11 作 §3。
- H-1 Approval 结果集与 `approve_for_*`：`options` 决定 `derived`（`approve_for_activity / approve_for_capability` 保留），候选的 `result` 一律 `approved_once`；`modify` 折入 `approved_once` 并记新 `params_digest`；`expired` 按 `on_expiry` 折入 `rejected` 或留 `pending`。
- H-2 `external_read` 不走审计快路径；只有 `local_read` 走快路径，`external_read` 走完整协议（Policy 通常 `allow`）。度量项"快路径占比"保留。
- **H-3 `fysun-dsh` 下 DSH 原生工具：选择 B——保留 DSH 原生 fs/shell 工具，经决策 11 的 `approval/request` 转发路径治理；`fysun-dsh` 重新订阅 DSH `tools/post-execute` 以获取 receipt。** 实施影响：
 - ADR-0002 D5 中"`fysun-tool-gate` 取消、不再订阅 `tools/post-execute`"需修订为"`fysun-tool-gate` 作为独立组件取消；`fysun-approval` 在 `approval/request` waterfall 拦截作为 DSH 原生工具的准入点，并订阅 `tools/post-execute` 作为 receipt 采集点"。
 - `fysun-dsh` 的 `describe()` 必须如实列出 DSH 原生工具于 `native_effect_tools[]`（不为空）。
 - 08 篇需定义：DSH 原生工具的 ActionIntent 在 `approval/request` 拦截点持久化（persist-before-dispatch 仍成立：拦截发生在工具体执行前）；receipt 由 `tools/post-execute` 产出；`tools/list` 过滤对 DSH 原生工具由 `fysun` profile 的 `tools.restrict` 承担（不可区分性由 DSH scope 机制保证，需登记为 M2b 验收项）。
 - 13 §6 conformance 表中"声明全部六控制点（`fysun-dsh`）"一列的 F3/F7/F9 状态：MCP 工具面经守卫；DSH 原生工具经 `approval/request` + `tools/post-execute` 路径；须如实注明"依赖 DSH waterfall 顺序保证，DSH 侧 `never` 策略优先于 waterfall 的行为必须被 `fysun` profile 禁止"（DSH 事实：`never` 策略在服务内部先于 waterfall 执行，`prepend` 的监听器也绕不过）。
 - 负例增：DSH approval policy 被设为 `never` 时 `fysun-dsh` 必须拒绝启动或 `runtime/disqualified`。
 - ADR-0007 D8 的 headless 查证项仍保留。
- H-4 新增 T11 审批面伪造；审批轰炸并入 T10。
- H-5 删除旧 04 §2.7 A2A 可信 Agent Card 例外。
- H-7 采纳：含非 `local_read` 类别的 Activity 恢复后缺省 `paused{reason: rearm_required}`，须 `activity.resume` 或 Policy `auto_resume`；纯只读 Activity 直接 `waiting`。
- H-8 agentgateway 关闭独立成 ADR-0012。
- H-9 开放问题清单统一于 12 §7，13 只引用。

### B-06 MCP 守卫规范（拆分 + 新建；依赖 00、02；ADR-0008/0011/0012 先定）

1. §1 定位：`fysund` 为唯一 MCP server 或前置；harness 不直接持有工具连接；与 DSH `guard/` 包无关；agentgateway 仅借用语义，自实现（ADR-0012）。
2. §2 `tools/list`：过滤规则 = Grant ∩ Policy ∩ `allowed-tools`；不可区分性：被过滤工具对 `tools/call` 返回与不存在工具相同的 MCP 错误，账本内记 `action-intent/rejected{reason: denied.grant | denied.policy}`；下游 `notifications/tools/list_changed` → 重新过滤与重分类。
3. §3 Effect 类别三源合一（ADR-0008）：六值 `local_read < external_read < local_mutation < external_mutation < credential_use < physical_action`（严重度序）；来源 (a) Capability `bounds.tool_effects[]`（必填），(b) Resource 目录登记的缺省类别，(c) Policy 覆盖；合成 = `max_severity(a, b)`，仅 Policy 可降低；(a)(b) 均缺 → `external_mutation`；MCP tool annotations 只作 (b) 的建议输入。
4. §4 `tools/call` pre / 执行 / post：pre = ActionIntent 持久化（幂等键；冲突 → `conflict.idempotency`）→ 类别合成 → Policy → Grant → 标签；post = Receipt + 结果标签 `untrusted_external` + `flags` 分类 → Policy 可 `modify`（脱敏）或 `deny`（不回传）；补偿新 Grant 规则。
5. §5 审计快路径：仅 `local_read`；`external_read` 走完整协议；事件 `audit/observed{execution_id, tool, params_digest, result_label, path: guard | hook}`。
6. §6 `tasks/*` 与 `elicitation/create`：elicitation 是 `fysund` 发起的审批载体，应答绑定 session Principal；Policy 可按 subject 强制带外；Runtime 文本输出永不构成审批面（T11）。
7. §7 守卫系统工具：`fysun.await_approval(approval_id)`（`local_read`，长轮询）、`fysun.pending_inputs()`（`local_read`）；出现在 `tools/list`，不受 `allowed-tools` 限制但受 Policy 控制。
8. §8 下游 MCP server 信任边界：凭据为 `SecretRef`，只在 `fysund` 连接时注入；每个下游 server 一条由 `fysund` 持有的 Streamable HTTP 会话（`Mcp-Session-Id` 不暴露给 harness）；会话失效 → 重连 + 重新 `tools/list`，在途 Effect → `outcome_unknown`；下游结果一律 `untrusted_external`；server 工具语义变更为 T2 供应链威胁。
9. §9 hooks.json 阻断路径（Level-1b）：`fysun hook pre-tool-use` 读取 harness 的 PreToolUse 载荷 → 调 `fysund` 本地 RPC → Policy `deny` 时退出码 2；只能 deny 或 abstain；不产生 Effect、无 receipt、无标签；账本记 `audit/observed{path: hook, verdict}` 或 `action-intent/rejected`；conformance 不计入。
10. §10 负例：被过滤工具可区分 → 失败；未分类工具走快路径 → 失败；`readOnlyHint = true` 且无其他来源却按 `local_read` → 失败；同幂等键不同参数被去重 → 失败；结果 `secret_shaped` 未经 Policy 直接回传 → 失败；`fysund` 依赖 agentgateway crate → 失败；`external_read` 走快路径 → 失败。

### C.2 新增 ADR

**ADR-0007 · Level-1 Runtime 原生工具、资格化与 conformance 范围**
- 背景：G1/G2/G3/G6；C2-7；借鉴 DeepSeek（能力位预检大声失败、scope 过滤、单调守卫层）。
- 决策：D1 `describe()` 必含 `native_effect_tools[]`、`describe_digest`；D2 Policy 可拒绝资格化或降级 conformance（13 §6 分列）；D3 hooks.json PreToolUse 阻断路径 = Level-1b，只能 deny/abstain，不计入主路径；D4 F5 Level-1 限定 + harness 自持凭据不防 + base URL 指向代理；D5 Level-1 context_view 渲染与 deliver_input 投递路径（07 §3）；D6 `start_execution` 大声失败；D7 Runtime 为通用 Resource 类型，资格化纪元 `runtime/disqualified`；D8 M2a 基线 = DSH headless（登记查证项）。
- 否决：把原生工具视为已受控（过度声明）；要求 harness 禁用全部原生工具作为资格化前提；以 hooks 作为 conformance 主路径。
- 负例：`describe()` 无 `native_effect_tools` 却 `runtime/qualified` → 失败；hooks deny 被记为 `action-intent/rejected` 以外的准入事件 → 失败；`describe_digest` 变化后无 `runtime/disqualified` 仍 `start_execution` → 失败；缺 required 控制点降级运行 → 失败。
- 后果：13 §6 表按类型分列；M2a 验收增项；Level-1 conformance 范围收窄如实声明。

**ADR-0008 · Effect 类别分类与只读判定**
- 决策：D1 六类别与严重度序；D2 三源合一与 `max_severity` 合成；D3 未分类 → `external_mutation`；D4 annotations 仅输入；D5 只有 `local_read` 走审计快路径 `audit/observed`，`external_read` 走完整协议（H-2）；D6 幂等冲突硬拒绝 `conflict.idempotency`；D7 补偿新 Grant + 新 ActionIntent。
- 否决：以 `readOnlyHint` 为依据；由 Runtime 自报类别；由 Capability 单方降级；`external_read` 白名单快路径。
- 负例：见 B-06 §10。
- 后果：`capability.register` 校验；Cedar `action` 实体按类别分组（ADR-0009）；M1 验收增项。

**ADR-0009 · Cedar 子集范围与实体模型**（关闭 08 Q7）
- D1 实体模型：principal 类型 `User / Execution / Runtime / ExternalAgent`；action 实体 = `Action::"<server>/<tool>"`，父组 `Action::"category:<effect_category>"`（六个）与 `Action::"capability:<id>"`；resource 类型 `Scope / Device / Account / McpServer`；context 固定键：`effect_category`、`params_digest`、`min_integrity`、`untrusted_params: Set<String>`、`result_flags: Set<String>`、`budget_remaining: Long`、`reversibility: String`、`runtime_type`、`control_points: Set<String>`、`native_effect_tools: Set<String>`、`assurance_level`、`offline: Bool`、`pending_approvals: Long`。
- D2 语法子集：`permit`/`forbid`；scope 约束 `==`、`in`、`is`；`when`/`unless`；运算符 `== != < <= > >= && || ! in has is like contains containsAll containsAny`、`if-then-else`；不收录模板、扩展类型（ip/decimal/datetime）、实体 tags。
- D3 `outcome` 四值表达约定：Cedar 只产 allow/deny，以策略注解承载 `@fysun_outcome("approve" | "modify")`、`@fysun_obligation("...")`、`@fysun_rule_id("...")`；评估规则：任一匹配 `forbid` → `deny`；否则匹配的 `permit` 中任一带 `approve` → `approve`；任一带 `modify` → `modify`；否则 `allow`；无匹配 → `deny`。
- D4 用 Cedar schema（JSON）校验策略，引用未知属性 → `policy.load` 拒绝。
- 本轮定不到（登记开放问题）：`modify` 改写表达式形式（注解字符串只能表达枚举改写如 `redact:<param>`、`clamp:<param>:<max>`）；`obligations[]` 枚举全集。CEL 互操作项删除（ADR-0012 使之失去必要性）。
- 负例：仓库出现自定义策略语法 → 失败；策略使用模板/扩展类型被 `policy.load` 接受 → 失败；两条 `permit` 同时带 `approve` 与 `allow` 时结果为 `allow` → 失败。

**ADR-0010 · 边缘离线账本一致性**（关闭 08 Q9）
- 决策：D1 节点归属唯一（home）；D2 事件带 `node_id` + `origin_seq`，中心 `seq` 为合并序；D3 预留预算 escrow Grant；D4 离线只允许预授权类别，`approve` 阻塞，edge 不决定 Approval；D5 合并写 `ledger/merged`，不改写 edge 事件；D6 冲突封闭枚举 `revoked_offline / policy_retired / home_violation / clock_skew` 与处置；D7 非 MVP，边缘阶段验收。
- 否决：CRDT 式自动合并预算；中心回滚 edge 事件；edge 本地 Principal 决定 Approval（多主体问题继续开放）。
- 负例：见 B-11 §3.6。
- 后果：事件通用字段增两项；`fysund-edge` 需要 escrow 与 digest 链；多主体一致性、Policy 分发一致性继续开放。

**ADR-0011 · Approval 结果集、事件配对与审批面来源**
- 决策：D1 结果集 `approved_once | rejected | cancelled | unavailable` 封闭，只有 `approved_once` 派生；`options`/`approve_for_*` 保留决定 `derived`（H-1）；D2 `approval/asked` / `approval/decided` 配对，任一无法提交 → `unavailable.approval` 拒绝整个请求；D3 请求不复制参数，引用 `action_intent_id` + `params_digest`；D4 审批事实不进模型可见面；D5 审批面只由 `fysund` 提供（Web UI / CLI / `fysund` 发起的 elicitation）；DSH：`fysun-dsh` 在 `approval/request` waterfall 拦截、不 `next()`、全部转 `fysund`，DSH 卡片失效；`fysun` profile 禁止 approval policy `never`；D6 审批轰炸：`approval_rate_limit`、`consecutive_rejections_alert` → Activity `blocked`；D7 `handoff_accept` 触发条件；D8 恢复后重新武装（H-7）。
- 否决：保留 `approved / denied / modified / expired` 开放状态集；允许 Runtime 渲染审批面；elicitation 应答不绑定 Principal；重启后无条件自动继续。
- 负例：`approval/decided` 无配对 `approval/asked` → 失败；`rejected` 派生 `grant/issued` → 失败；`approval/asked` 载荷含参数明文 → 失败；DSH 原生卡片应答落账 → 失败；聊天文本"批准"产生 `approval/decided` → 失败；超过 `approval_rate_limit` 仍 `approval/asked` → 失败；恢复后未 `activity/resumed` 出现新 `effect/authorized` → 失败。

**ADR-0012 · `fysun-mcp-guard` 自实现，关闭 agentgateway 复用评估**（关闭 08 Q10 / ADR-0002 D7）
- 决策：仅借用 Pass/Reject/Mutated 语义与 Cedar 格式；不作为库嵌入、不进程前置；F1 不变。
- 否决：库嵌入（引入外部依赖节奏与 TCB 扩大）；进程前置（多一跳、双份策略评估、与 `fysund` 单写者语义重叠）。
- 负例：`fysund` 依赖 agentgateway crate 或 fork → 失败；守卫结果语义出现三值以外 → 失败。
- 后果：README 许可证段去 agentgateway；CEL 互操作项删除。

## E. 事件族与错误码变更清单

事件：删除
`approval/requested`、`approval/granted`、`approval/denied`、`approval/modified`、`approval/expired`

事件：新增
- `approval/asked{approval_id, subject, subject_ref{action_intent_id?, params_digest?, object_ref?}, policy_decision, expiry}`
- `approval/decided{approval_id, result: approved_once | rejected | cancelled | unavailable, option?, params_digest?, decided_by, derived[]}`
- `audit/observed{execution_id, tool, effect_category: local_read, params_digest, result_label, path: guard | hook, verdict?}`
- `execution/waiting{reason: trigger | approval | input}`
- `runtime/disqualified{resource_id, reason: describe_changed | bundle_changed | policy_revoked | adapter_precondition_failed}`
- `node/registered | node/online | node/offline`
- `ledger/merged{node_id, from_seq, to_seq, digest}`、`ledger/conflict{node_id, kind, refs[]}`

事件：字段变更
- 通用字段增 `node_id`、`origin_seq`
- `runtime/qualified` 增 `native_effect_tools[]`、`describe_digest`、`bundle_digest`
- `grant/issued` 增 `escrow?: {node_id}`；由 Approval 派生的 `grant/issued` / `adjustment/applied` 的 `approval_id` 只可指向 `result = approved_once` 的 Approval
- `action-intent/rejected` 的 `reason` 取值增 `conflict.idempotency`、`unavailable.approval`
- `activity/paused` 增 `reason: user | rearm_required | ...`
- 准入类事件（携带 `policy_decision`）：`effect/authorized`、`action-intent/rejected`、`approval/asked`、`grant/issued`、`memory/admitted`、`memory/rejected`、`runtime/qualified`

错误码：新增
- `conflict.idempotency`：同一幂等键、不同 canonical 参数；硬拒绝
- `unavailable.approval`：`approval/asked` 或 `approval/decided` 无法提交，或审批面不可用；整个请求拒绝

错误码：语义变更
- `not_runnable.environment`：新增触发条件（缺 required 控制点、Runtime 未资格化 / 已 `disqualified`、Policy 拒绝的 `native_effect_tools`、适配器前置条件不满足如 DSH approval policy `never`）
- `denied.grant` / `denied.policy`（被过滤工具）：对外 MCP 错误形状必须与未知工具一致，账本内保留真实原因
- `needs_human(approval_id)`：Level-1 下的投递路径见 07 §3
